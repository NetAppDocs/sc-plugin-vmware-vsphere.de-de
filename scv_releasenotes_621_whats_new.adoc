= Neuerungen in SnapCenter Plug-in for VMware vSphere 6.2.1
:allow-uri-read: 


[role="lead"]
SnapCenter Plug-in for VMware vSphere 6.2.1 ist ein Wartungsrelease. Es aktualisiert die mit der Appliance ausgelieferte Drittanbietersoftware und enthält Fehlerbehebungen für Probleme, die seit dem Release von SnapCenter Plug-in for VMware vSphere 6.2 festgestellt wurden.



[[updated-components]]
== Aktualisierte Komponenten

|===
| Komponente | SnapCenter Plug-in for VMware vSphere 6.2.1 


| Java Laufzeitumgebung | OpenJDK 21.0.12 


| .NET Laufzeit | .NET 10.0.11 


| Betriebssystem der Appliance | Debian 13 
|===


[[fixed-issues]]
== Behobene Probleme

Es empfiehlt sich, vor dem Upgrade auf ein Release die bekannten Probleme zu prüfen, die in diesem Release behoben wurden.

|===
| Bug-ID | Beschreibung 


| VMDP-7072 | Cloud-managed ONTAP auf Oracle Cloud kann als Storage-System hinzugefügt werden. 


| VMDP-7052 | Bei der Wiederherstellung einer VM an einem anderen Speicherort bleibt die VM-Storage-Richtlinie erhalten, sodass die Wiederherstellung für VMs, die eine andere als die Standardrichtlinie verwenden, nicht mehr abgelehnt wird. 


| VMDP-7027 | Die Support-Log-Bundles enthalten die Liste der konfigurierten Storage-Systeme. 


| VMDP-6987 | Das Anhängen oder Wiederherstellen einer virtuellen Festplatte schlägt nicht mehr fehl, wenn vCenter den Datenspeicher kurzzeitig als nicht verfügbar meldet. 


| VMDP-6965 | Die Seite „Zeitpläne“ wird nun auch dann geladen, wenn ein Zeitplaneintrag unvollständig ist. 


| VMDP-6952 | Wenn ein Benutzer nicht berechtigt ist, eine Ressourcengruppe zu löschen, wird die Berechtigungsmeldung angezeigt. 


| VMDP-6939 | Die Managementplattform meldet nicht mehr, dass VMware Tools fehlen. 


| VMDP-6935 | Beim Durchsuchen eines Backups zur Wiederherstellung einzelner Dateien tritt kein Fehler mehr auf. 


| VMDP-6933 | Das Deployment einer neuen Appliance schlägt bei der erstmaligen Einrichtung nicht mehr fehl. 


| VMDP-6931 | Die Bereinigung sekundärer Backups wartet nicht mehr stundenlang auf ein einzelnes, nicht erreichbares Volume. Andere Volumes werden weiterhin verarbeitet. 


| VMDP-6817 | Durch das Umbenennen eines ONTAP Volumes bleiben sekundäre Backups nicht mehr unter dem alten Namen erhalten und zeigen keine Einträge mehr an, die nicht mehr gültig sind. 
|===
